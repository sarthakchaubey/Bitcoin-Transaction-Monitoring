# Bitcoin Transaction Forensics — Technical Write-up

## Problem Statement Summary

Bitcoin transaction activity is transparent but difficult to triage manually at scale. This project is designed as an offline forensic pipeline that combines transaction structure, wallet clustering, network metadata, anomaly detection, graph communities, and investigator-readable explanations to prioritize suspicious wallets.

The repository currently contains the Phase 0–9 scaffolding and tested modules, but the checkout used for this write-up does not contain the claimed Phase 1 dataset generator, `data/raw` transactions, `data/ground_truth/ground_truth.csv`, or a GeoLite2 database. Consequently, no honest end-to-end model metrics are reported below.

## Approach / Architecture

```text
transactions.csv/json/xml
          |
          v
  ingestion + validation
          |
          v
  offline GeoLite2 enrichment
          |
          v
 wallet/transaction/IP graph
          |
          v
 cluster + wallet features
          |
          v
 Isolation Forest + Louvain
          |
          v
 ensemble risk ranking
          |
          v
 SHAP reasons + evidence subgraphs
          |
          v
 Streamlit investigator dashboard
```

### Ingestion

The ingestion layer parses CSV, JSON, and XML representations of the same transaction schema. It normalizes timestamps, IPs, ports, fees, addresses, and amounts, rejects malformed rows into a log, and removes duplicate transaction IDs while retaining the first occurrence.

### Correlation and graph construction

Each wallet, transaction, and broadcast IP becomes a typed node in a NetworkX `MultiDiGraph`. Directed edges preserve input, output, and broadcast semantics. Common-input ownership clustering groups addresses that appear together as transaction inputs; a conservative change-address heuristic can merge likely change outputs into the sender cluster.

### ML detection

The primary unsupervised model is Isolation Forest over the scaled wallet/cluster feature matrix. It is appropriate when labels are hidden or sparse and provides a fast anomaly ranking. Louvain community detection operates on a weighted undirected wallet projection and contributes a second network-level risk signal. The ensemble combines anomaly and community scores with the default `(0.5, 0.5)` weighting, rather than relying on either behavioral outliers or graph structure alone.

### Explainability

SHAP explanations are generated for the Isolation Forest, using TreeSHAP where supported and a small-background KernelSHAP fallback otherwise. The top signed contributions are converted into investigator-readable reason sentences and packaged with a JSON-safe local graph neighborhood, confidence label, and best-effort pattern hint.

### Dashboard

The Streamlit dashboard loads `data/evidence_packages.json`, allows score/confidence/pattern/wallet filtering, displays the reason sentence and SHAP contribution data, and renders the serialized local subgraph through the existing graph view.

## Dataset

The intended dataset is a synthetic transaction corpus generated by Phase 1 with injected illicit behavior patterns and a hidden `ground_truth.csv` mapping wallet IDs to `is_illicit` and `pattern_type`. The expected evaluation patterns include peeling chains, fan-in/fan-out hubs, rapid cash-out activity, and shared-IP clusters.

The current checkout contains no generator implementation and no generated raw or ground-truth files. The checked-in `data/generate_evidence.py` is a dashboard demonstration fixture, not a transaction generator and not suitable for model evaluation. GeoIP enrichment is fully offline and requires the user-provided `geoip/GeoLite2-City.mmdb`; that file is also absent from this checkout by design.

## Model Choice & Justification

Isolation Forest is the reliable default because it trains quickly, works without labels, and captures multivariate outliers in wallet behavior. Louvain is a practical graph baseline because it exposes tightly connected transaction communities without requiring a costly graph neural network training loop.

The two models see complementary evidence: Isolation Forest measures unusual wallet features such as bursts, amount fragmentation, and shared IP counts, while Louvain-derived risk measures network context. Their normalized scores are combined using equal default weights: 50% anomaly score and 50% community score. These weights are configurable and should be tuned only using a separate validation procedure, never by leaking hidden ground truth into model features.

## Explainability Method

The explanation layer uses SHAP contributions for the Isolation Forest score. Each alert receives signed top features, where positive values increase anomaly risk and negative values decrease it. These values are mapped to plain-English phrases such as “distinct counterparties sending value to the wallet” and “wallet clusters sharing the same broadcast IP.”

Evidence records also include a confidence label, a best-effort pattern hint, and a serialized one-hop transaction/IP subgraph. This matters operationally because an investigator can see both the statistical reason for prioritization and the concrete network neighborhood to inspect next.

## Limitations & Honest Caveats

- Synthetic data does not capture the full complexity, adversarial adaptation, address reuse, exchange behavior, or temporal patterns of real Bitcoin activity.
- Common-input and change-address heuristics can create both false-positive and false-negative wallet clusters.
- The illustrative high-risk geography list is not an authoritative FATF or threat-intelligence source.
- Isolation Forest contamination and ensemble weights are dataset- and operating-point-specific.
- Community risk is an interpretable heuristic, not proof of illicit behavior.
- SHAP explains the fitted anomaly model; it does not establish causality or criminal intent.
- No end-to-end metric should be trusted until the real Phase 1 generator, ground truth, and GeoLite2 file are present and the evaluation scripts complete successfully.

## Future Work

- Upgrade community modeling to a GraphSAGE model with held-out weak supervision from ground truth.
- Migrate large graph workloads to Neo4j or another graph store.
- Add live or streaming ingestion with incremental feature updates.
- Integrate reviewed threat-intelligence feeds for high-risk geography and ASN signals.
- Add calibration, temporal validation, and analyst feedback loops for threshold selection.
